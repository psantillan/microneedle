Build on it

The board answers token ids over HTTP. Everything else is one module you can import straight from it.

Ask it something

import { Needle } from "http://BOARD/needle.js";
const n = await Needle.connect({ base: "http://BOARD" });

const tools = [{
  name: "get_weather",
  description: "Get current weather for a location",
  parameters: { type: "object",
                properties: { location: { type: "string" } },
                required: ["location"] }
}];

const r = await n.call("What's the weather in Oslo?", tools);
r.call    // { name: "get_weather", arguments: { location: "Oslo" } }
r.stats   // { promptTokens, generatedTokens, encMs, tokMs, ... }

Run what it picks

n.register("get_weather", async ({ location }) => {
  const w = await fetch(`https://wttr.in/${location}?format=j1`);
  return (await w.json()).current_condition[0];
});

const out = await n.run(r.call);   // null when nothing is registered

Tokenize and detokenize

n.encode("What's the weather in Oslo?")   // [4279, 743, ...]
n.decode([4279, 743])                     // "What is"

// the exact encoder input the model sees:
//   [query tokens] <tools> [tools-JSON tokens]
n.prompt(query, tools).ids

// Same code path at training time and at inference time, so a dataset
// built with this cannot drift from what the board actually reads.

curl -s http://BOARD/api/tokens \
  -H 'Content-Type: application/json' \

GET /vocab.txt is the 8192-entry vocabulary. GET /api/status reports the kernel self-tests the board ran at boot.

What this is

Needle is a 26M-parameter encoder-decoder from Cactus Compute. It turns a request plus a list of tools into a function call. No feed-forward layers anywhere, which is most of why it fits.

The forward pass here is a from-scratch C99 and RISC-V vector-assembly port. Weights are int4 with an int8 embedding, 14.66 MiB resident. On a fixed set of eight cases the board matches the reference implementation token for token.

The board serves this page. Tokenizing happens in your browser. The model runs on the chip. Encoder runs once per request and scales with prompt length, so one tool is about 0.4 s and a full 271-token catalogue about 5.4 s (5.6 s warm-cached) (last board-certified figures). Decode is 89–108 ms/token. Nothing is cached.
